## Crear libretas (0.15 puntos)

Para simplificar, añadiremos a la pantalla de nueva nota un botón "Nueva libreta" que, al pulsarlo, mostrará un cuadro de diálogo (*alert*) con un campo de texto para escribir el nombre.

!!! note "Nuevo en SwiftUI: `.alert`"
    En SwiftUI, un cuadro de diálogo no se "muestra" llamando a un método, sino que se **declara** asociado a una variable `Bool` de estado: el diálogo aparece cuando la variable se pone a `true`, y SwiftUI la vuelve a poner a `false` automáticamente cuando el usuario pulsa cualquiera de sus botones. Es la misma idea de siempre: no modificamos la pantalla, modificamos una variable.

    ```swift
    .alert("Título", isPresented: $mostrando) {
        //los campos de texto y los botones del diálogo
    } message: {
        Text("Mensaje que aparece debajo del título")
    }
    ```

    Dentro del diálogo podemos poner campos de texto (`TextField`) y botones. Un botón con `role: .cancel` es el de cancelar.

En `NuevaNotaView`, añade estas dos variables de estado:

```swift
@State private var mostrandoNuevaLibreta = false
@State private var nombreLibreta = ""
```

y este botón dentro del `VStack`, por ejemplo justo encima del área de texto:

```swift
Button("Nueva libreta") {
    nombreLibreta = ""
    mostrandoNuevaLibreta = true
}
.alert("Nueva libreta", isPresented: $mostrandoNuevaLibreta) {
    TextField("Nombre", text: $nombreLibreta)
    Button("Crear") {
        crearLibreta()
    }
    Button("Cancelar", role: .cancel) { }
} message: {
    Text("Escribe el nombre para la nueva libreta")
}
```

- Escribe la función `crearLibreta()`, que debe **crear la libreta** con el nombre escrito y **guardarla** usando Core Data. Muestra en el `mensaje` de la pantalla si se ha creado correctamente o el error que se haya producido.

## Seleccionar la libreta (0.15 puntos)

Para que el usuario pueda elegir en qué libreta guardar la nota vamos a usar un selector (`Picker`).

!!! note "Nuevo en SwiftUI: `Picker`"
    Un `Picker` muestra una serie de opciones y deja seleccionar una. Se conecta mediante un *binding* a una variable de estado, la *selección*, que contiene la opción elegida. Cada opción se identifica con el modificador `.tag`, que indica qué valor tomará la selección si el usuario la elige:

    ```swift
    @State private var color = "rojo"

    Picker("Color", selection: $color) {
        Text("Rojo").tag("rojo")
        Text("Verde").tag("verde")
    }
    ```

    **El valor de `.tag` debe ser exactamente del mismo tipo que la selección**. Si no lo es, el compilador no se queja, pero al elegir una opción la selección no cambia. Es un error muy habitual.

    Cuando las opciones salen de una colección de datos usamos `ForEach`, que genera una vista por cada elemento, igual que hace `List` con las filas.

- Declara en `NuevaNotaView` una propiedad `libretas` con `@FetchRequest` que obtenga todas las libretas ordenadas alfabéticamente por nombre.
- Añade una variable de estado para la libreta seleccionada. Es opcional, porque una nota puede no tener libreta:

```swift
@State private var libretaSeleccionada: Libreta?
```

- Añade el `Picker` junto al botón "Nueva libreta". Por ejemplo, en un `HStack`:

```swift
HStack {
    Picker("Libreta", selection: $libretaSeleccionada) {
        Text("Sin libreta").tag(nil as Libreta?)
        ForEach(libretas) { libreta in
            Text(libreta.nombre ?? "").tag(libreta as Libreta?)
        }
    }
    Spacer()
    //...aquí el botón "Nueva libreta" con su .alert
}
```

Fíjate en el `as Libreta?` de los `.tag`: como la selección es de tipo `Libreta?`, los valores de las opciones tienen que serlo también.

Comprueba que al crear una libreta nueva aparece inmediatamente en el selector. No has tenido que hacer nada para ello: como `libretas` es una `@FetchRequest`, la vista se actualiza sola cuando se crea una libreta en el contexto.

## Asociar una libreta a la nota actual (0.15 puntos)

Falta que cuando se guarde la nota, se le asocie la libreta que aparece seleccionada en el *picker*. Igual que asignas el "texto" y la "fecha" de la nota, **asígnale también la libreta seleccionada usando la relación "a uno" entre `Nota` y `Libreta`**. Si está seleccionada la opción "Sin libreta", la nota quedará sin libreta.

## Nombres de libreta únicos (0.2 puntos)

No debe poder haber dos libretas con el mismo nombre. Si el usuario intenta crear una libreta con un nombre que ya existe, la app debe mostrarle un aviso en el `mensaje` de la pantalla y no crearla.

- Añade al modelo la restricción necesaria.
- Elige la *merge policy* adecuada para conseguir el comportamiento pedido.
- Trata el posible error al guardar la libreta.

Para comprobar que funciona correctamente, prueba esta secuencia: crea una libreta "Trabajo", intenta crear otra "Trabajo" (debe aparecer el aviso y **no debe aparecer una segunda "Trabajo" en el selector**), y a continuación crea una libreta "Casa" y guarda una nota. **Las dos últimas operaciones tienen que funcionar con normalidad.** Si no es así, repasa en la sección de CRUD qué ocurre con los objetos que han provocado un error al guardar.

## Validar el nombre de la libreta (0.2 puntos)

El nombre de una libreta no puede estar vacío ni estar formado solo por espacios. Si no es válido, igual que en el apartado anterior, la app mostrará un aviso (con un mensaje que explique el problema) y no creará la libreta.

- La validación debe hacerse **en el modelo de Core Data**, no comprobando el texto en la vista antes de crear la libreta. Así se cumplirá desde cualquier parte de la aplicación que cree o modifique libretas.
- Una parte de la condición se puede expresar con las reglas del `Data Model Inspector`, pero otra no: piensa cuál necesita una validación propia.

> Pista: para saber si una cadena está formada solo por espacios puedes quitárselos con `trimmingCharacters(in: .whitespaces)` y ver si el resultado está vacío.

Prueba a crear libretas con nombre vacío, con solo espacios, con un nombre repetido, y finalmente con un nombre válido, que debe crearse sin problemas.

## Mostrar la libreta al listar las notas (opcional, sin puntuación)

En `ListaNotasView`, muestra debajo del texto de cada nota el nombre de su libreta, en letra más pequeña y en color secundario (o "Sin libreta" si no tiene).

Para practicar, extrae la fila a una subvista `FilaNota`, que reciba la nota como propiedad.

!!! note "Nuevo en SwiftUI: `@ObservedObject`"
    Cuando una subvista recibe un objeto de Core Data, conviene declararlo con `@ObservedObject`:

    ```swift
    struct FilaNota: View {
        @ObservedObject var nota: Nota
        //...
    }
    ```

    Así, si el objeto cambia (por ejemplo, si se modifica el texto de la nota), la subvista se redibuja. Sin `@ObservedObject` la subvista mostraría el texto antiguo hasta que algo más provocara que se redibujara. Los objetos de Core Data son `ObservableObject`, un tipo de objeto que avisa a las vistas que lo observan cuando cambia alguna de sus propiedades.
