Vamos a completar la pestaña donde se pueden consultar las notas que tenemos almacenadas. Las listaremos en una lista (`List`) y por el momento se verán todas, no se podrán filtrar (añadiremos esa posibilidad cuando veamos la sintaxis de las consultas).

## *Fetch requests*

Para recuperar objetos de Core Data se usa una ***fetch request***, que sería algo así como una consulta. Por ejemplo, para obtener todas las instancias de una entidad debemos crear y ejecutar una *fetch request* sin condiciones (como si fuera un `SELECT` sin `WHERE`). Para obtener todas las notas haríamos algo como:

```swift
let request: NSFetchRequest<Nota> = Nota.fetchRequest()
//la línea anterior la podríamos poner también como
//let request = NSFetchRequest<Nota>(entityName: "Nota")

//ejecutamos la consulta
//suponiendo que "contexto" sea el contexto de persistencia
let notas = try contexto.fetch(request)
for nota in notas {
    print(nota.texto ?? "")
}
```

Al ejecutar la *fetch request* con el método `fetch` del contexto obtenemos un array con los resultados, en este caso de tipo `[Nota]`.

!!! warning "Indica siempre el tipo de la *fetch request*"
    En la primera línea es importante poner el tipo `NSFetchRequest<Nota>`. Si escribimos solo `let request = Nota.fetchRequest()`, el compilador puede dar un error de ambigüedad (*Ambiguous use of 'fetchRequest()'*) o tomar la versión de `NSManagedObject`, que devuelve resultados genéricos con los que no podremos acceder a `texto` o `fecha`.

> Los atributos de las entidades se generan como opcionales (`texto` es `String?`, `fecha` es `Date?`), aunque en el modelo no los hayamos marcado como tales. Por eso usamos `?? ""` en lugar de desempaquetar con `!`.

Ejecutar una *fetch request* con `fetch` es útil cuando necesitamos los datos en nuestro código. Pero si lo que queremos es **mostrar los resultados en una vista**, SwiftUI nos ofrece una forma mucho más cómoda.

## `@FetchRequest`

En una vista de SwiftUI podemos declarar una *fetch request* con el *property wrapper* `@FetchRequest`:

```swift
struct MiLista: View {
    @FetchRequest(sortDescriptors: [NSSortDescriptor(keyPath: \Nota.fecha, ascending: false)])
    private var notas: FetchedResults<Nota>

    var body: some View {
        List(notas) { nota in
            Text(nota.texto ?? "")
        }
    }
}
```

Con esto:

- SwiftUI ejecuta la consulta usando el contexto que hay en el entorno, y deja los resultados en la propiedad `notas`. Su tipo es `FetchedResults<Nota>`, pero podemos usarla como si fuera un array: recorrerla, acceder a un elemento por su posición, ver cuántos hay con `count`...
- Los resultados se ordenan según los criterios que indicamos en `sortDescriptors`: en el ejemplo, por fecha de más reciente a más antigua. Veremos la ordenación con detalle en la sesión de consultas. Si no queremos ordenar, podemos pasar un array vacío (`[]`), aunque entonces el orden no está garantizado.
- **La vista se actualiza sola cuando cambian los datos**. Si se crea, modifica o borra una nota en el contexto, desde esta vista o desde cualquier otra, la lista se vuelve a dibujar con los datos actualizados. No hay que volver a ejecutar la consulta ni avisar a la vista.

Esto último es muy importante, y encaja perfectamente con la filosofía de SwiftUI: igual que una vista se redibuja cuando cambia una variable `@State`, una vista con `@FetchRequest` se redibuja cuando cambian los datos de Core Data que muestra.

> Como en `List(notas)` no hemos indicado ningún `id`, te puedes preguntar cómo distingue SwiftUI unas filas de otras. Los objetos gestionados por Core Data son `Identifiable`: cada uno tiene un identificador único que asigna el propio Core Data.

## El código de la pantalla de listado

**Implementa `ListaNotasView`** para que muestre todas las notas en una lista, de más reciente a más antigua, usando `@FetchRequest`. De cada nota mostraremos por ahora solo el texto.

Para comprobar que funciona:

1. Ejecuta la app, crea una nota en la pestaña "Nueva" y cambia a la pestaña "Lista": la nota debería aparecer sin necesidad de hacer nada más. Las notas que creaste en la sección anterior también deberían estar.
2. Vuelve a la pestaña "Nueva", crea otra nota y vuelve a la lista: debe aparecer la primera, ya que es la más reciente.
3. Detén la app y vuelve a ejecutarla: las notas siguen ahí.
4. Escribe la *preview* de `ListaNotasView`, con el contexto de `PersistenceController.preview` en el entorno, como se explica en la sección anterior. En la *preview* deberían aparecer las 5 notas de ejemplo. Fíjate en que estas notas no aparecen al ejecutar la app, ya que la *preview* usa una base de datos distinta, en memoria.

> Si la *preview* falla con un mensaje sobre que no encuentra la entidad (*NSFetchRequest could not locate an NSEntityDescription for entity name 'Nota'*), es que no has puesto el contexto en su entorno.
